# Retrieval Lab

A search engine over a Simple Wikipedia corpus that compares six ranking
models side by side: BM25, TF-IDF, Hiemstra_LM, PL2 (via PyTerrier, with RM3
relevance feedback), BERT (sentence-transformers), and ELMo
(tensorflow_hub). Also includes a small character-level RNN that offers live
autocomplete suggestions in the search box.

## Project structure

```
data/
    simplewiki-latest-pages-articles.xml   <- you provide this
index/                                     <- generated by build_index.py
    pyterrier_index/
    docstore.pkl
    bert_embeddings.pkl
    elmo_embeddings.pkl
    rnn_model.keras
    rnn_chars.pkl
src/
    build_index.py       <- run once to build everything in index/
    text_processing.py   <- shared wikitext cleaning + preprocessing
    autocomplete.py       <- RNN training + live completion
    search_service.py    <- loads index/embeddings, handles queries
    check_index.py        <- diagnostic script, verifies a build is correct
static/
    styles.css
    app.js
templates/
    index.html
app.py                    <- Flask app, run this to start the site
requirements.txt
```

## Setup

**Python version matters here.** This project needs **Python 3.12**, not
3.13. On Intel Macs specifically, both `torch` and `tensorflow` stopped
shipping Intel-compatible wheels for newer Python versions (torch 2.3+ and
recent tensorflow releases are Apple Silicon / Linux / Windows only). The
pinned versions in `requirements.txt` (`torch==2.2.2`,
`tensorflow==2.16.2`) are the last ones with Intel Mac support, and they
cap out at Python 3.12.

```
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

If you're on the python.org installer build of Python (not Homebrew) and
hit `SSL: CERTIFICATE_VERIFY_FAILED` errors when downloading models, run:

```
open "/Applications/Python 3.12/Install Certificates.command"
```

This installer doesn't wire itself into macOS's certificate store
automatically, that command does it once.

## Building the index

Place your Simple Wikipedia XML dump at `data/simplewiki-latest-pages-articles.xml`,
then from the project root:

```
python src/build_index.py
```

This parses the dump, strips wikitext markup and redirect stubs, builds
the PyTerrier index, and computes BERT and ELMo embeddings plus the RNN
autocomplete model. Expect this to take **a few hours**, almost entirely
the ELMo step (roughly 13-14 seconds per document). It prints progress
every 25 documents so you can track it.

**If it's interrupted partway through**, just rerun the same command. The
ELMo step checkpoints its progress to disk and will resume from where it
left off rather than starting over.

Before committing to a full run, it's worth doing a quick smoke test by
temporarily setting `MAX_ARTICLES` near the top of `build_index.py` to
something small (like 50), confirming the run finishes cleanly with no
errors, then setting it back and running the real build.

To verify a completed build:

```
python src/check_index.py
```

This checks that document counts match across the index, docstore, and
both embedding files, flags any NaN vectors, and runs a sample query
through every model so you can sanity-check the results.

## Running the app

```
python app.py
```

Then open `http://127.0.0.1:5000`. The first search using BERT or ELMo
will be noticeably slower than the rest, both models load lazily on
first use rather than at startup.

## Notes

- **Redirect pages and empty stubs are dropped** during indexing, they
  carry no real content. Expect the final article count to be lower than
  the number of pages read from the XML dump, roughly 20-25% get filtered
  out for this particular dump.
- **RM3 relevance feedback** only applies to the four lexical models
  (BM25, TF-IDF, Hiemstra_LM, PL2). It doesn't apply to BERT or ELMo,
  since RM3 expands a query string, which embedding-based search has no
  use for.
- **The RNN autocomplete is intentionally small** (a single `SimpleRNN`
  layer, trained on a capped slice of the corpus). It's a working
  feature, not a polished one, expect short, sometimes nonsensical
  completions rather than real words. It stops generating at the first
  predicted space, so it effectively completes only the current word.
